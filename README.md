# TROF simulations

This repository is the executable study model for the **Thermal Resource Orchestration Framework (TROF)**: waste-heat recovery from a 5 MW IT colocation facility in three synthetic Indian Tier-2-city operating scenarios. Captured 45/35 °C liquid-loop heat is upgraded by modular high-temperature heat pumps and dispatched to district hot water, process heat, a single-effect absorption chiller, an Organic Rankine Cycle (ORC), or thermal storage.

The repository was built to make every paper result reproducible. Reported outputs must be generated by the code. Expected result ranges are not encoded in the implementation and are never optimization targets.

## Scientific boundary and invariants

Recovery is measured at the heat-pump evaporator:

`absorbed waste heat = delivered heat × (1 − 1/COP)`

Compressor electricity is not recovered heat. Storage discharge is also not counted again; heat is counted when the store is charged. The 30% of IT heat that misses the capture loop remains explicitly unrecoverable, while captured heat not absorbed by TROF is explicitly rejected.

At every timestep the source, heat-pump, and main-store residuals are asserted within `1e-9 kW`; the capture-buffer residual is asserted to the same standard as an additional check. A violation raises immediately. Every timeseries CSV contains all four residual columns, while summary CSVs contain their run maxima.

The capture-loop buffer sits upstream of the required source accounting boundary. Accordingly:

- gross `site_captured_kw` is the capture fraction times IT heat;
- boundary `captured_kw` is gross capture plus buffer discharge minus buffer charge;
- boundary `captured_kw = hp_absorbed_kw + rejected_kw` at every step;
- the full audit includes buffer energy change and loss so gross site capture also closes.

Dry cooling is applied whenever ambient is at least 10 K below the 35 °C loop return, before mechanical rejection. This prevents the counterfactual cooling load from being inflated.

Community demand not supplied by TROF is served by the counterfactual LPG boilers or mechanical chiller. The outputs distinguish this `fallback_demand_percent` from true `unmet_demand_percent`; fallback is costed, while actual unmet demand is zero because the specified backup plant is not capacity-limited.

## What is assumed—not measured

All three 30-day, 15-minute scenarios are parametric design cases. They are not weather, utility, or customer measurements. Ambient, IT load, and community demand use documented diurnal shapes with AR(1) noise. Grid outages follow a published-roster abstraction with independent daily edge jitter (`σ = 0.35 h`). The controller knows the roster but never the realised jitter.

| Scenario | City | Season | Ambient mean/swing | IT utilisation | Grid hours/day |
|---|---|---|---:|---:|---:|
| A | Nagpur | Peak summer (May) | 34.0/8.0 °C | 0.75 | 16 |
| B | Bhopal | Monsoon/grid stress (Aug) | 26.5/4.5 °C | 0.62 | 12 |
| C | Coimbatore | Winter/industrial (Jan) | 24.0/7.0 °C | 0.70 | 20* |

\*The source specification states 18 grid hours/day for Scenario C but supplies only the 19:00–23:00 outage window, which implies 20. The executable model treats the explicit window as authoritative and records this discrepancy rather than inventing an unlisted outage.

Physical values and tariffs are centralized in dataclasses in `trof/components.py`. Every physical constant has a nearby paper, handbook, catalogue-range, or explicit study-design source comment. The generated `results/component_parameters.csv` is the appendix-ready version.

## Controllers

- **MPC:** a 12-hour PuLP/CBC MILP, replanned every two steps. It models four individual 500 kW heat-pump modules and their binary turndown states, pathway splits, charge/discharge exclusion, storage bounds, absorption/ORC limits, source availability, and scheduled grid availability.
- **Tuned heuristic:** ranks useful pathways by marginal avoided cost, accounts for ambient-sensitive alternatives, skips uneconomic routes, and uses the store for grid/outage arbitrage.
- **Naive heuristic:** fixed priority without an economic screen. It is intentionally weak but still serves all useful community pathways before speculative ORC dispatch.

The causal seasonal-naive forecaster blends the same clock slot from up to six prior days with weights `[0.55, 0.25, 0.12, 0.05, 0.02, 0.01]`. Every candidate index must be strictly earlier than the control origin. Cold start uses only an expanding past mean or static design defaults. Forecast arrays are copied and checked not to share memory with realised arrays.

## Installation and tests

Python 3.11 and the free CBC solver bundled with PuLP are sufficient.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
pytest
```

The tests exercise component monotonicity and caps, all balance residuals over a full 30-day run and randomized inputs, and the no-lookahead invariant under future-data perturbations.

## Run the study

From the repository root:

```bash
python study.py
python figures.py
```

The full design contains 45 main runs, 150 demand-sweep runs, 3,000 Monte Carlo controller runs (500 parameter draws for each scenario and two controllers), and three perfect-forecast runs. A single-core full execution is intentionally substantial because no surrogate or hardcoded result replaces the MILP. Use a wall-clock budget and invoke the identical command again to resume:

```bash
python study.py --budget-seconds 14400
```

Each completed run is appended immediately to `results/run_registry.csv`; existing run IDs are skipped. Main and ablation timeseries are retained under `results/timeseries/`. Sweep and Monte Carlo runs retain complete metrics and maximum residuals in the registry without multi-gigabyte redundant timeseries. For a short engineering smoke test only (not paper results):

```bash
python study.py --days 2 --min-seeds 1 --mc-draws 2 --solver-time-limit 1
```

The driver rejects any time-limited MPC step that CBC does not certify as optimal. Do not mix smoke-test and 30-day registries; run smoke tests in a temporary checkout or remove only the known smoke-test files before the publication run.

## Outputs

`study.py` creates:

- `main_results.csv`: mean and standard deviation across seeds;
- `controller_comparison.csv`: MPC improvement against both baselines;
- `energy_balance_audit.csv`: inspection-ready energy closure;
- `demand_scale_sweep.csv`: recovery and MPC value at ×0.5, 1, 2, 3, and 5 demand;
- `monte_carlo_runs.csv` and `monte_carlo_summary.csv`: the improvement distribution;
- `perfect_forecast_ablation.csv`;
- `component_parameters.csv` and `forecast_errors.csv`.

`figures.py` reads those CSVs—never internal constants—and exports all available figures as PDF and 300 dpi JPEG. It reports incomplete prerequisites instead of inventing missing plots.

## Interpretation guardrails

An air-cooled ORC may remain idle when the heat-pump lift consumes more valuable electricity than the ORC generates. That is a valid negative result. Likewise, recovered fraction may be limited by sink demand rather than source heat. Neither behavior should be “fixed” through parameter tuning. If results differ from earlier contextual ranges, inspect the balance audit, component outputs, forecast errors, and controller economics and report the difference.
